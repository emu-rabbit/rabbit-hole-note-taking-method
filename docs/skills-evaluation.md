## 實際涵蓋的範圍

虛構人物林予安的資料跨 2016–2026：16 筆初始記錄、3 回合腳本訪談、2 筆後續更新。材料包含三段朋友／合作關係、一件停止又換形式繼續的作品、工作與創作交錯、普通週末、矛盾日期和不同時期的感受。全部為測試而原創。

演練依序做了起步、來源預覽與匯入、精讀、三輪訪談、寫作、串聯及後續維護。訪談是分回合供應的腳本，不是真人訪談；實際問題和腳本原題分別保留。最終有 23 篇實質敘事頁，連同來源、入口與維護共 59 份 Markdown。頁數只描述範圍，驗收以文章與實際查找結果為準。

另以小型案例實跑英文起步、回憶保存、故事與來源路線、日期衝突修訂；繁中小型案例也測了只談一題且不保存、來源指令字串、未支援 ZIP 與分開的本機閱讀草稿。

## 第一輪：查得到，讀起來仍有阻力

第一位獨立讀者先從 README 走完人物概覽、三條短路線與四段人生時期，再做十二項查找。這一輪沒有先讀答案資料，也沒有靠全文搜尋或檔案樹找路。查找階段已受先前閱讀影響，並非完全盲測。

十二題都有實質回答，常見路徑是「README → 索引 → 文章 → 來源」。作品分工、停止的版本、當年開心與後來害怕、普通週末都找得到。逐頁核對 23 篇敘事後，仍留下這些具體修訂：

| 初版問題 | skills 收斂成的做法 | 重做後的證據 |
| --- | --- | --- |
| 多篇正文反覆教讀者「可以停」「不必…」，打斷場景 | 入口交代選擇，正文自然結束，頁尾保留簡短導覽 | 三條路線重讀順暢，原有生活細節仍在 |

## 後續更新：讓理解繼續成立

舊文章沒有遺失，既有 ID 沒有改動，原來 19 筆來源位元組保持不變。修改回到既有故事、人物、作品、年表與入口，並保留理解更新的原因。

## 修訂後再讀

整理後的 skills 共用少量原則，各自保留目的、流程與完成條件。執行指令和載入參考文字約減少 28%；作者的兩份方法原文保持不變。另做了一次指令設計審查，修正「聊天草稿」分支不應順便更新檔案的歧義。

最終重跑另建新庫，依序匯入 16／3／2 筆來源，再接入按新版指令修訂的人寫頁。保留原來源身份與定位，沒有手改舊的不可變來源。原評審重新走讀並核對十二題；另外一位未看過前稿的讀者，從 README 走入兩三條路線，回答人物、普通日子、合作分工與活動現況四題。

兩種閱讀都得到實質結果。新讀者能說出予安會享受沒有進度的週末，朋友各有自己的時間與尚未談完的話；也能分辨未完成互動地圖和後來紙本作品，以及內部試播和公開活動。最後補好來源索引的就地更正、工作查找入口與概覽重複句。

例如〈星期六的岸邊〉現在自然接到這一段：

> 從學生時期就認識的朋友許葦傳訊息問晚上要不要看展，予安說今天只想在外面坐著；她回一張自己也坐在公車站的照片。後來兩人沒有碰面。

這段有相處、有普通生活，原話與場景能接回 S08。閱讀理解沒有依賴額外的人格判斷或成長結論。

## 驗證方式與限制

- 本機完成 51 個 Python 測試、22 個 Node 網站／SEO 回歸與七個官方 skill 格式驗證；檢查可依使用指南的命令在本機重跑。
- 深度案例最終 59 頁結構檢查無問題，21 筆來源逐字一致，來源原始檔雜湊有效，167 個引用錨點逐一開檔核對。三批重匯均為 unchanged。公開 fixture 另以自動測試核對來源、結構與可達性。
- 深度案例是繁中；英文驗證是較小的起步／修訂情境。沒有宣稱所有語言、人生經歷或 agent 都會得到同樣品質。
- 走讀透過實際 Markdown 與來源檔案完成；未實測 Obsidian 的視覺點擊、螢幕閱讀器或每種 Markdown 客戶端。Wiki links 需要相容閱讀器。
- 來源頁仍保留技術 JSON，放在原話之後供需要時查核。工具沒有原生社群 API、OCR、語音轉錄、定時同步、Windows 支援或自動發布功能。
- 腳本對話、合成資料與有限查找任務不能證明真實訪談舒適度、任意資料的隱私安全或普遍寫作品質。實際使用仍由本人決定材料與分享範圍，並閱讀與修正重要理解。
