## 本輪：五個完整任務入口

這輪把入口改成建立、匯入、訪談、整理維護、準備分享。寫作、串聯、索引和回讀成為共用完成流程。主指令每份 24–29 行，方法原文之外的執行指令與參考文字約比前一版少 16%；保留必要的來源與授權界線，沒有把每個測試個案變成禁止條款。

### 自然訪談確實會接著整理

- **繁中既有庫：** 從先前 59 頁虛構林予安筆記開始，只提出「訪談我」，再按實際問題提供三個回答，最後說「今天先到這裡吧」。agent 自己保存問答、寫出試播後洗杯子的日常片段，接回人物、作品、年表、索引、閱讀地圖與閱讀進度；沒有另外要求寫文章或加連結。首次產物為 61 頁，新增 2 頁、修改 12 頁。
- **英文從零開始：** 只提出「Help me start a rabbit hole. I'd like to talk about the first time I moved home.」並提供資料夾、語言與保存範圍。兩輪問答後自然停止，留下 8 頁小庫，不需要再次調用訪談。獨立讀者從 README 回答人物、朋友角色、第一晚感受和日期依據，再核讀全部 8 頁與原話。
- **英文匯入與維護：** 後續提供三篇搬家貼文，再提供日期更正。agent 自己補入故事、人物與時間線，先保留八月底回憶和九月貼文的差異，收到更正後才改為 2019-09-07；也分清 Rowan 交還桌子給 Kit 的日期和 Kit 再交給阿姨的未知日期。最終 14 頁逐頁核讀，舊訪談、三篇匯入來源、原始輸入與台帳均保持不變。

中文重播由未看前輪產物與評審的整理者執行，共 62 頁，新增 3 頁、修改 15 頁。提供的 transcript 在讀取時也顯示了前輪最後的完成回覆，因此稱為獨立重播，沒有聲稱嚴格盲測。它沒有重新訪問真人；只是從同一段已結束的虛構問答重新完成整理。

### 保存與分享界線

- 「這次只聊，不保存」的英文回合：整個隔離工作區 69 個檔案的前後雜湊完全一致，對話沒有寫入來源、轉錄或進度紀錄。
- 「檢查，但不要改檔」：17 個主庫檔案逐一核對不變。
- 給姊姊看的本機草稿：agent 自行選出三個檔案，移除電話內容、把 Kit 改稱「a school friend」，來源節錄同步處理。九段節錄逐一比對原文，十二個內部連結與目標都成立；主庫不變，也沒有上傳或傳送。草稿仍保留地點、日期等可識別細節，不宣稱匿名。
- 安裝驗證涵蓋五技能完整安裝、移除原始 checkout 後執行、中英初始化、預覽不寫入、重匯與修訂、舊版衝突與回滾。舊版不會被自動刪除或覆寫。

### 本輪驗證範圍與限制

本機完成 **67 個 Python 測試、26 個 Node 網站／SEO 測試、五個官方 skill 格式驗證**，中英公開範例各 56 頁建置成功。中英首頁實際畫面已檢查，仍使用原本四步和單一註解位置。網站與公開方法都接受「回憶／既有記錄」兩種起點，技能內方法副本逐位元組相同；私人正式庫沒有修改。

內容驗收是有限的合成人物與分回合模擬，不能保證真人訪談舒適度或每個 agent 的品質。區塊引用已依檔案與實際錨點核對，**未測 native Obsidian 的點擊行為**；主庫需要支援 Wiki／區塊連結的閱讀器，分享草稿使用普通 Markdown 標題連結。執行環境為 macOS、Python 3.13；Linux 與最低 Python 3.10 仍未實跑。平台 ZIP／API、OCR、語音轉錄、自動同步與發布仍不在工具組內。新回歸測試可重驗結構、來源與檔案界線，不能替代上述逐頁內容評審。

## 先前的跨十年深度案例

以下保留前一輪的實際過程。它當時按起步、匯入、訪談、寫作與串聯分段演練，所以不能單靠它證明「只說訪談我」就會自動收尾；這也是本輪另做自然請求驗收的原因。

這次把技術檢查與內容走讀分開進行。先建立一個跨十年的全虛構人物庫，再讓未參與寫作的讀者從入口認識這個人、找資料、回讀來源。初版通過連結檢查後，仍因閱讀問題回去修訂 skills 和文章。

## 實際涵蓋的範圍

虛構人物林予安的資料跨 2016–2026：16 筆初始記錄、3 回合腳本訪談、2 筆後續更新。材料包含三段朋友／合作關係、一件停止又換形式繼續的作品、工作與創作交錯、普通週末、矛盾日期和不同時期的感受。全部為測試而原創。

演練依序做了起步、來源預覽與匯入、精讀、三輪訪談、寫作、串聯及後續維護。訪談是分回合供應的腳本，不是真人訪談；實際問題和腳本原題分別保留。最終有 23 篇實質敘事頁，連同來源、入口與維護共 59 份 Markdown。頁數只描述範圍，驗收以文章與實際查找結果為準。

另以小型案例實跑英文起步、回憶保存、故事與來源路線、日期衝突修訂；繁中小型案例也測了只談一題且不保存、來源指令字串、未支援 ZIP 與分開的本機閱讀草稿。

## 第一輪：查得到，讀起來仍有阻力

第一位獨立讀者先從 README 走完人物概覽、三條短路線與四段人生時期，再做十二項查找。這一輪沒有先讀答案資料，也沒有靠全文搜尋或檔案樹找路。查找階段已受先前閱讀影響，並非完全盲測。

十二題都有實質回答，常見路徑是「README → 索引 → 文章 → 來源」。作品分工、停止的版本、當年開心與後來害怕、普通週末都找得到。逐頁核對 23 篇敘事後，仍留下這些具體修訂：

| 初版問題 | skills 收斂成的做法 | 重做後的證據 |
| --- | --- | --- |
| 多篇正文反覆教讀者「可以停」「不必…」，打斷場景 | 入口交代選擇，正文自然結束，頁尾保留簡短導覽 | 三條路線重讀順暢，原有生活細節仍在 |
| 單篇初登場的人物／作品背景不足 | 在自然出場處補當下所需的簡短背景 | 雨夜錄音先說明聲音計畫，週六與搬家篇交代許葦的朋友位置 |
| 首發開頭先講日期校勘，場景在後面 | 先讓讀者進場，核對說明放在相關句旁、註腳或時間段 | 首發從聲音小刊物擺上桌寫起，日期依據仍可回查 |
| 原話之前先有約三十行機器 JSON | 人讀的來源資訊與原文前置，技術紀錄後置 | 新建重跑的 21 筆來源全文都在 JSON 前面 |
| 無依據代詞、請茶變成承諾、日記月份變成到職月份 | 沿用有依據的稱呼，保留行動與時間的精確程度 | 用予安或省略主詞；保留「也請…」；寫成四月記錄中已轉職 |
| 更新被接在原來的頁尾導航後面 | 把新理解融回所屬時間或主題，再通讀整篇 | 十一月試播整合進人物與作品正文，導航回到尾端 |

來源選取也做了實際調整：混合檔裡的排除材料先分開，由提供者交付獨立允許子集，再進入匯入。這個經驗收斂成批次邊界原則；匯入器會保存整個輸入的原始位元組。

## 修訂後再讀

整理後的 skills 共用少量原則，各自保留目的、流程與完成條件。執行指令和載入參考文字約減少 28%；當時的兩份方法原文保持不變。另做了一次指令設計審查，修正「聊天草稿」分支不應順便更新檔案的歧義。

最終重跑另建新庫，依序匯入 16／3／2 筆來源，再接入按新版指令修訂的人寫頁。保留原來源身份與定位，沒有手改舊的不可變來源。原評審重新走讀並核對十二題；另外一位未看過前稿的讀者，從 README 走入兩三條路線，回答人物、普通日子、合作分工與活動現況四題。

兩種閱讀都得到實質結果。新讀者能說出予安會享受沒有進度的週末，朋友各有自己的時間與尚未談完的話；也能分辨未完成互動地圖和後來紙本作品，以及內部試播和公開活動。最後補好來源索引的就地更正、工作查找入口與概覽重複句。

例如〈星期六的岸邊〉現在自然接到這一段：

> 從學生時期就認識的朋友許葦傳訊息問晚上要不要看展，予安說今天只想在外面坐著；她回一張自己也坐在公車站的照片。後來兩人沒有碰面。

這段有相處、有普通生活，原話與場景能接回 S08。閱讀理解沒有依賴額外的人格判斷或成長結論。

## 驗證方式與限制

- 前一輪當時完成 51 個 Python 測試、23 個 Node 網站／SEO 回歸與七個官方 skill 格式驗證；檢查可依使用指南的命令在本機重跑。
- 深度案例最終 59 頁結構檢查無問題，21 筆來源逐字一致，來源原始檔雜湊有效，167 個引用錨點逐一開檔核對。三批重匯均為 unchanged。公開 fixture 另以自動測試核對來源、結構與可達性。
- 深度案例是繁中；英文驗證是較小的起步／修訂情境。沒有宣稱所有語言、人生經歷或 agent 都會得到同樣品質。
- 走讀透過實際 Markdown 與來源檔案完成；未實測 Obsidian 的視覺點擊、螢幕閱讀器或每種 Markdown 客戶端。Wiki links 需要相容閱讀器。
- 來源頁仍保留技術 JSON，放在原話之後供需要時查核。此輪驗收早於 Windows 支援，不能用來描述現行平台範圍；原生社群 API、OCR、語音轉錄、定時同步與自動發布仍不在工具組內。
- 腳本對話、合成資料與有限查找任務不能證明真實訪談舒適度、任意資料的隱私安全或普遍寫作品質。實際使用仍由本人決定材料與分享範圍，並閱讀與修正重要理解。
