# 用 skills 開始自己的兔子洞

[English](skills.en.md) · [回到專案](../README.md) · [完整筆記法](../examples/emu-rabbit-tw/00_入口/兔子洞筆記法.md)

可以從一段想留下的回憶開始，不必先準備一生的資料。這五個 skills 對應五種需求：建立兔子洞、匯入資料、訪談、整理與維護，以及準備分享版本。說出想完成的事，agent 會負責保存來源、寫成可讀筆記、串起連結，並實際走讀檢查。

它們是給支援 SKILL.md 的 agent 使用的工具組，附本機 Python 輔助程式，處理你挑選的來源檔案。留下哪些材料、怎麼敘述、是否分享，都由你決定。公開範例示範方法；你的兔子洞從自己的材料開始。

## 安裝一次，按需要使用

本機安裝器與輔助程式目前支援 macOS、Linux，需要 Python 3.10 以上；尚未支援 Windows。沒有 Python 套件依賴；網站開發才另外需要 Node.js 22 以上。先用 `python3 --version` 確認版本，如果電腦上的 python3 較舊，請改用你已安裝的新版 Python。不要把私人資料放進這個公開程式庫。

```sh
git clone https://github.com/emu-rabbit/rabbit-hole-notes.git
cd rabbit-hole-notes
python3 scripts/validate-skills.py
python3 scripts/install-skills.py
```

最後一行只預覽。確認後安裝：

```sh
python3 scripts/install-skills.py --apply
```

預設放在 `$CODEX_HOME/skills`，未設定時為 `~/.codex/skills`。也可以用 `--dest /你的/skills/資料夾` 指定目的地，例如另一個相容 agent 的技能目錄。五個 skills 共用 `rabbit-hole-start` 裡的筆記法、內部參考與本機工具，必須一起安裝。安裝後在下一個回合確認是否能選到；若目前客戶端尚未重新載入，重新開啟它。

安裝器會先檢查全部檔案、連結和衝突，不覆寫既有 skills，也不修改全域設定。遇到同名版本或舊版入口時會停止：先備份並由你決定如何把既有兔子洞 skills 移出技能目錄，再安裝完整新版；目前沒有自動更新或移除指令。其他 skills 不受影響。使用相容 agent 的載入方式可能不同；此處驗證的是檔案安裝與 Codex 格式，沒有宣稱各家客戶端都已實測。

## 五個 skills 各自完成什麼

| Skill | 何時用 | 完成後留下什麼 |
| --- | --- | --- |
| `$rabbit-hole-start` | 建立自己的兔子洞 | 私人小骨架，接著開始訪談；在同意的保存範圍內完成第一篇筆記與入口 |
| `$rabbit-hole-import` | 把挑選的本機材料整理進來 | 保留原始輸入與來源，將實際讀過的批次整理成筆記並接回導覽 |
| `$rabbit-hole-interview` | 回想經歷、相處與感受 | 自然的對話；告一段落時，在同意的範圍內保存敘述、更新相關筆記與入口 |
| `$rabbit-hole-maintain` | 檢查、補寫、修正或改善閱讀路線 | 唯讀檢查結果，或獲准範圍內的敘事、來源、索引與路線更新 |
| `$rabbit-hole-share` | 準備給特定讀者看的版本 | agent 挑選並列出建議檔案與必要依賴，準備與主版本分開的本機草稿供審閱 |

每個入口都會把當次工作做到可閱讀、可查來源、可以接著走。寫作、串聯、歸檔、索引與走讀是 agent 的責任，共用的寫作與連結原則放在內部參考文件；`write` 和 `connect` 不再是需要另外叫用的 skills。你只需要說明目標、材料範圍與希望保留的位置。

保存範圍確立後，agent 會完成範圍內的整理，不必每寫一篇或補一個連結就重新詢問。未允許保存、希望先聊聊，或只要唯讀檢查時，就維持該範圍。分享是另一個決定，準備本機草稿不等於允許上傳或交付。

## 五種自然的請求

直接說你想完成什麼就好。第一次使用時，agent 會確認必要的資料夾、語言與保存範圍；已有兔子洞時，沿原本的位置和結構繼續。

### rabbit-hole-start：從一段回憶開始

> 幫我建立自己的兔子洞，從第一次搬家的回憶開始聊。

agent 建立私人小骨架後，就接著問第一題，不必另叫訪談 skill。在同意的保存範圍內，對話告一段落時會留下有日期與說話者的回憶來源、一篇短故事，以及從 README 走到故事和來源的入口。也可以指定只建立骨架，或先聊天不保存。

### rabbit-hole-import：整理挑選好的貼文

可以先用社群平台的「下載／匯出資料」功能，取得自己的**社群貼文匯出檔案**，再挑出願意交給 agent 讀取與保存的檔案、日期範圍或貼文，作為匯入素材。也可以直接使用手邊已挑好的社群貼文，不必先匯出整個帳號。

> 我從社群平台下載了匯出檔案。請把其中我挑好的這三篇搬家社群貼文整理進兔子洞，讓這段生活更完整。

agent 會先確認匯出格式與允許處理的範圍，再依可用工具整理成可匯入的檔案。平台原生 ZIP／JSON 不一定能直接匯入，支援格式與限制見下方的[本機工具說明](#實際可執行的本機工具)。

agent 保留允許匯入的原始輸入、作者、時間、來源 ID 與台帳，再把實際讀過的內容補入相關故事、人物或生活筆記，更新入口、索引與閱讀進度並走讀檢查。大批材料會分段閱讀，不會把「已匯入」當成「已理解」。如果只想保存來源、不改敘事，可以指定「只歸檔」；相同資料重跑不會重複建立來源。

### rabbit-hole-interview：慢慢回想一次合作

> 陪我聊聊第一次和朋友做小刊物的經過，把這段回憶留進兔子洞。

agent 順著回答追問，每次一兩題。聊到自然的停點，會在已確立的保存範圍內，保留有說話者與敘述日期的來源，把故事、人物與作品接回現有筆記，再更新導覽並走讀。當年的感受和今天的回想分開，不確定的地方仍然保留。你隨時可以說先不保存或排除某一段。

### rabbit-hole-maintain：把新理解接回舊筆記

> 我找到小刊物真正的首發日期了，幫我修正兔子洞裡相關的內容。

agent 讀過新依據後，沿原有身份更新相關作品、故事與年表，保留舊來源並說明理解改變的原因。這個入口也能補寫文章、整理連結與短閱讀路線；只要求檢查時則維持唯讀，列出發現與建議。每次都留下實際閱讀進度和可接續的位置。

### rabbit-hole-share：先做給家人看的閱讀草稿

> 幫我準備一份給姊姊看的搬家故事版本，我想先看看。

agent 根據讀者和主題，挑選並列出建議包含的確切檔案，檢查來源節錄、附件和連結依賴，準備與主版本分開的本機草稿。你可以逐頁審閱必要背景、刪改和仍待確認的內容，再決定交付哪些檔案給誰。準備草稿不會自動傳送、上傳或公開。

### 需要指定 skill 時

如果客戶端沒有自動選到適合的入口，在請求前加上上表的名稱即可，例如 `$rabbit-hole-interview`。不需要再列一串寫作、連結或索引命令。

## 第一次完成後

第一次做完，agent 應實際確認四件事，並把可以開始閱讀的入口交給你：

1. 同意保存的回憶已成為有說話者、敘述日期和不確定處的來源，不需要為此先做一份社群匯出。
2. 一篇短文能獨立讀懂，註腳能回到真正的來源段落。
3. README 能帶到文章，來源索引不再寫「尚無來源」，也能回到入口。
4. 維護筆記記下實際讀過的材料，以及下次從哪裡繼續。

接著，agent 要像第一次來的讀者讀一遍：能理解場景、認識這個人、找到依據，也知道在哪裡可以停嗎？即使結構檢查通過，讀起來卡住的文章和路線仍需調整。

## 實際可執行的本機工具

核心程式隨 `rabbit-hole-start` 一起安裝。以下以預設目錄示範，`/你的/…` 要換成自己的路徑：

```sh
TOOL="${CODEX_HOME:-$HOME/.codex}/skills/rabbit-hole-start/scripts/rabbit_hole.py"
python3 "$TOOL" init --vault /你的/新私人兔子洞 --name '你的稱呼' --lang zh-TW
# 看過預覽後，在同一命令加上 --apply 才會寫入。
python3 "$TOOL" import --vault /你的/私人兔子洞 --input /你的/已挑選貼文.json \
  --namespace selected-posts --owner '你的稱呼' --author '實際說話者'
python3 "$TOOL" check --vault /你的/私人兔子洞
```

`init` 和 `import` 預設只預覽；`check` 永遠唯讀。初始化不覆寫現有路徑，寫入命令拒絕 Git 儲存庫內或經過符號連結的私人資料夾。程式不建立 remote、不推送、不改分享設定、不開網路連線。更多參數、檔案位置與失敗處理見 [CLI 說明](../skills/rabbit-hole-start/references/cli.md)。

匯入支援 UTF-8 文字、Markdown、約定格式的 JSON 陣列與 JSONL，每個輸入檔最多 16 MiB。保留來源 ID、說話者、事件／發表／敘述時間、原始位元組與雜湊。相同材料重跑不重複；相同 ID 的變動保存成新修訂，不覆蓋舊來源。沒有穩定 ID 時按內容識別，修改過的文字會視為新來源，不能假稱已自動對上同一篇。

匯入會保留整個輸入檔的原始位元組。若大檔混有允許和排除的內容，請先提供獨立的允許批次；若挑選本身就得讀到排除內容，先請提供者準備乾淨的子集。

[來源格式與虛構範例](../skills/rabbit-hole-import/references/source-formats.md) 說明怎麼準備材料。**Facebook、Instagram、Threads、X、LINE、Discord、Email 等平台的原生 ZIP／API 尚無專用轉接器。** agent 可在你授權的範圍內查看實際格式、挑選與轉換，保留映射和來源，但這不是程式已支援那些平台。圖片、影音、OCR、語音轉錄、定時同步也未包含。

## 讓資料和理解分清楚

來源成功匯入，不代表 agent 已經讀完。人的原話、他人發言、整理者理解和 AI 建議各有位置；貼文日期、事情發生的時間和今天回憶的時間也要分開。新材料會接回原有人物、故事或作品，不因角色改變就另造一個人。

檢查器能找部分本機連結、錨點、重複 ID 和來源完整性問題。它不是完整 Markdown 解析器，也不能證明敘事正確、匿名化完成或可以公開。仍要逐頁讀過，實際走一次入口、故事和來源。

「本機工具」只表示輔助程式不連網，**不代表你使用的 AI 服務或同步資料夾不會接觸內容**。請自己選擇信任的處理環境和材料範圍。工具不提供加密、存取控制或自動隱私判定。分享 skill 刻意採逐檔選擇與人工審閱，沒有自動打包／發布命令；不會把排除維護區當成已經安全。

## 驗證與開發

```sh
python3 scripts/validate-skills.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
npm run check
```

測試用虛構素材涵蓋兩種語言的起步、可重跑匯入、修訂保留、來源注入、路徑界線、安裝隔離和既有網站。測試不是對所有 agent 行為或私密資料的安全保證。skills 內的完整筆記法與公開範例保持一致，工具慣例另放在 [conventions.md](../skills/rabbit-hole-start/references/conventions.md)。整體 repo 的授權說明仍適用，這裡沒有替任何來源或作品追加重用授權。
